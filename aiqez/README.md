# AIQEZ Creative AI Studio — պատվերների կայք

Հեռախոսների համար նախատեսված, ամբողջությամբ հայերեն պատվերների կայք։
Աշխատում է առանց build-ի՝ սովորական HTML/CSS/JS։

- **Կայքը՝** https://aiqez-studio-am.netlify.app
- **Պատվերները՝** Netlify → aiqez-studio-am → **Forms** → **order**
  (https://app.netlify.com/projects/aiqez-studio-am/forms)

## Ինչպես են ընդունվում պատվերները

Պատվերի ձևը (`index.html`-ի `<form name="order" data-netlify="true">`) միացված է
**Netlify Forms**-ին։ Ուղարկելիս `order-service.js`-ը կայքին ուղարկում է
`multipart/form-data` հարցում հետևյալ դաշտերով՝

| Դաշտ | Պարունակություն |
|---|---|
| `order_number` | Պատվերի համար, օր.՝ `AQ-261119-K3F9` (ցույց է տրվում նաև հաճախորդին) |
| `name`, `contact` | Անուն, հեռախոս կամ Telegram |
| `service`, `price` | Ծառայության անունը և գինը (`config.js`-ից) |
| `language`, `date` | Լեզու, ցանկալի ամսաթիվ |
| `details` | Պատվերի մանրամասներ |
| `photo_count`, `photo1`…`photo5` | Կցված լուսանկարները |
| `bot-field` | Սպամի դեմ թաքնված դաշտ (honeypot) |

**Լուսանկարների սահմանները** (Netlify Forms-ի կանոններով)՝ մեկ ֆայլ մեկ դաշտում,
ամբողջ հարցումը՝ մինչև 8 ՄԲ։ Դրա համար կայքը ընդունում է մինչև 5 նկար,
յուրաքանչյուրը փոքրացնում է մինչև 2048 պիքսել JPEG հենց հեռախոսում, և բոլորը
միասին պետք է լինեն մինչև 7 ՄԲ։ Սահմանները՝ `config.js`-ում (`maxPhotos`,
`maxUploadMB`)։ `maxPhotos`-ը փոխելիս ավելացրու նույնքան `photoN` դաշտ `index.html`-ում։

Նոր դաշտ ավելացնելիս այն պետք է ավելացնել և՛ `index.html`-ի ձևում, և՛
`order-service.js`-ում, այլապես Netlify-ը այն չի պահի։

## Փորձնական ռեժիմ

`config.js`-ում `demoMode: true` դնելու դեպքում ոչինչ չի ուղարկվում, իսկ կայքում
կրկին երևում են «Փորձնական ռեժիմ» նշումները։ Հիմա՝ `demoMode: false` (իրական պատվերներ)։

| Ֆայլ | Ինչ է պարունակում |
|---|---|

| `index.html` | Էջը և Netlify Forms-ի «order» ձևը |
| `styles.css` | Դիզայն |
| `app.js` | Ստուգում, նկարների փոքրացում և նախադիտում, ամփոփում |
| `order-service.js` | Պատվերի ուղարկում Netlify Forms |
| `tests/smoke.test.mjs` | Ավտոմատ ստուգում (փորձնական և իրական ուղարկում) |
| `netlify/functions/`, `netlify/lib/` | Վճարման սերվերային մաս (Netlify Functions) |
| `payment/` | Վճարման արդյունքի և փորձնական բանկի էջեր |
| `netlify.toml`, `package.json` | Netlify-ի կարգավորում և սերվերի կախվածություններ |

### Գների փոփոխություն

```js
price: null,      // → «Արժեքը՝ ըստ պատվերի»
price: 25000,     // → «25 000 ֏»
priceFrom: true,  // → «սկսած 25 000 ֏»
```

```bash
NODE_PATH=$(npm root -g) node aiqez/tests/smoke.test.mjs
```

## Հրապարակում Netlify-ում

Base directory՝ `aiqez`, Build command՝ դատարկ, Publish directory՝ `.`։
Netlify-ում պետք է միացված լինի **Forms → Form detection**։

## Քարտով վճարում

**Ընթացքը.** հաճախորդը լրացնում է պատվերը → ամփոփման մեջ տեսնում է հաստատված գինը →
«Պատվիրել և վճարել քարտով» → սերվերը (`create-payment`) գինը վերցնում է `config.js`-ից,
ստեղծում է պատվերի համար և բանկում վճարման պատվեր → պատվերը նկարներով պահվում է Netlify
Forms-ում → հաճախորդն անցնում է բանկի ապահով էջ → բանկը վերադարձնում է
`payment-return`, որը **բանկին սերվերային հարցմամբ** ստուգում է կարգավիճակը և գումարը →
`payment/success.html`, `cancelled.html` կամ `failed.html`։

- Կոճակը երևում է միայն այն ծառայությունների համար, որոնց `price`-ը թիվ է, և `priceFrom`-ը՝ `false`։
  Գինը փոխելուց հետո կայքը պետք է նորից հրապարակել (սերվերը նույնպես կարդում է `config.js`-ը)։
- Հաճախորդից եկած գումարը չի օգտագործվում։ URL-ի պարամետրերին և բանկի callback-ի
  բովանդակությանը չենք վստահում. «Վճարված» է նշվում միայն բանկի `status` պատասխանով,
  երբ գումարն ու արժույթը (AMD, 051) համընկնում են։
- Վճարումների կարգավիճակները պահվում են **Netlify Blobs**-ում (`aiqez-payments`)։
  Հաստատված վճարումը գրանցվում է նաև Netlify Forms-ի **payment** ձևում, որտեղ տերը այն տեսնում է
  (և կարող է ծանուցում ստանալ)։ Պատվերի «order» ձևում կա «payment» դաշտ՝ վճարման եղանակով։

| Ֆունկցիա | Ինչ է անում |
|---|---|
| `payment-config` | Վճարումը միացված է՞, փորձնական է՞ |
| `create-payment` | Նոր վճարում կամ կրկնակի փորձ (`retryOrder`) |
| `payment-return` | Բանկից վերադարձ → ստուգում → արդյունքի էջ |
| `payment-status` | Կարգավիճակը արդյունքի էջերի համար |
| `payment-callback` | Բանկի սերվերային ծանուցում → նորից ստուգում բանկում |
| `test-bank` | Միայն փորձնական ռեժիմում՝ փորձնական բանկի էջի համար |

### Ռեժիմներ (Netlify → Project configuration → Environment variables)

| Փոփոխական | Արժեք |
|---|---|
| `PAYMENT_PROVIDER` | չնշված կամ `test` → **փորձնական բանկ** (գումար չի գանձվում, էջը հստակ նշված է). `arca` → իրական բանկ |
| `ARCA_USERNAME` | Բանկի տրամադրած API օգտանուն (**գաղտնի**) |
| `ARCA_PASSWORD` | Բանկի տրամադրած API գաղտնաբառ (**գաղտնի**) |
| `ARCA_API_URL` | REST հասցեն. փորձարկման՝ `https://ipaytest.arca.am:8445/payment/rest`, իրականը՝ բանկից |

`PAYMENT_PROVIDER=arca`, բայց առանց օգտանուն/գաղտնաբառի → քարտով վճարումն անջատվում է։

### Ինչ պետք է ստանալ բանկից (ArCa vPOS / էքվայրինգ)

1. Էլեկտրոնային էքվայրինգի (ինտերնետ-վաճառքի) պայմանագիր և merchant հաշիվ։
2. **Թեստային** API օգտանուն և գաղտնաբառ, թեստային քարտեր, REST API փաստաթուղթ։
3. **Իրական** API օգտանուն և գաղտնաբառ, իրական API հասցեն։
4. Հաստատում, որ միացումը **մեկփուլ** է (վճարումը միանգամից գանձվում է, orderStatus = 2)։
5. Բանկին տրվող հասցեներ՝
   - կայքը՝ `https://aiqez-studio-am.netlify.app`
   - callback՝ `https://aiqez-studio-am.netlify.app/.netlify/functions/payment-callback`
   - վերադարձի հասցեները ֆունկցիան ինքն է ուղարկում յուրաքանչյուր վճարման հետ։
6. Արժույթ՝ AMD (051), վճարման էջի լեզուներ՝ hy, ru, en։

Եթե բանկը օգտագործում է ոչ ArCa համակարգ (օր.՝ Ameriabank vPOS), պետք է ավելացնել նոր
ադապտեր `netlify/lib/providers/`-ում՝ նույն `register()` և `status()` ֆունկցիաներով։
